# BochiBochiEditor CLI棚卸

## 配布フォルダの構成

```
BochiBochiEditor.exe   … 本体（dll などを内蔵した 1 ファイル。.NET 8 デスクトップランタイムが必要）
resource\              … アイコン・img・ini・lang・txt
resource\mapassist\    … マップ作成補助の指定（見本として FR 日本語版・エメラルド英語版のタイルセット用を同梱。保存するとここに増える）
settings.ini          … 初回の終了時に自動で作られる（画面の配置・言語など）
error.log             … 読み込みに失敗したときだけ作られる
```

配布フォルダの作り方: `dotnet publish BochiBochiEditor\BochiBochiEditor.csproj -p:PublishProfile=FolderProfile`（出力先は `publish\`）。
開発中のビルド（`dotnet build`）は従来どおり dll などが exe の隣に出る。補助ファイルはどちらも `resource\` の下。

## GUIの使い方（マップエディタ単体起動）

GUIはマップエディタ専用になりました。起動するとメイン画面メニューは出ず、いきなりマップエディタが開きます。
他のエディター（ポケモン、アイテム、トレーナーなど）はGUIからは呼び出せません。CLIコマンドとしてのみ残っています。

### 起動からマップ編集まで
1. `BochiBochiEditor.exe` を起動する（`.gba` ファイルを exe にドラッグ＆ドロップして起動すると、そのROMを読み込んだ状態で開く）
2. 入口画面の **ROM を開く…** か、左上の **ROMを選択** ボタンで `.gba` を開く
3. 「マップを選択」ツリーからマップを選ぶと、そのまま編集できる
4. 各タブの「変更を反映」「変更を保存」はメモリ上のROMへの反映
5. 左上の **ROMを保存** ボタンでファイルへ書き出す（未反映の変更があれば先に反映するか確認される）

ROMを読み込むまでは「ROMを選択」以外のUIは無効化されます。ウィンドウタイトルに読み込み中のROMファイル名が表示されます。

### 開ける ROM
- ファイアレッド（日本語版 `BPRJ`・**英語版 `BPRE` 1.0**）、エメラルド（日本語版 `BPEJ`・英語版 `BPEE`）と、その改造版。
- **decomp ベースで作り直したエメラルド**（pokeemerald-expansion など）: プログラムの並びが元の ROM と違っていても、マップ・地形データ・マップ名・人物のパレットの表を、データの形から探して開きます。タイルセットの絵は、LZ77 のほかに pokeemerald-expansion の新しい圧縮（smol）と、圧縮なしを読めます。
- **拡張した形式のエメラルド**（PokeKyoto など。ブロック番号が 11 ビットで、タイルセットごとの容量の表を持つもの）: マップの表示と、マップの並び・移動エリア・イベントの編集と保存ができます。ブロック・タイル・タイルセットを書き換える機能（ブロック編集・チップ取り込み・マップタイルの取り込み・タイルセットやパレットの新規作成など）は、この形式ではまだ使えません（押すと案内が出ます）。出現ポケモンのタブも、この形式では読めません。1024 番以降のタイルを使うブロックは、絵が正しく出ません。
- 処理の途中で想定外のエラーが起きたときは、内容を `error.log` に書いて、案内を 1 回だけ出します（同じエラーが続いている間は、窓を出しません）。

### 入口画面（ROM を読み込んでいないとき）
ROM を読み込んでいない間は、メイン画面に入口画面が重なって出ます。ROM を開くと消えます。ROM を読んだ後も、上の **ホーム** ボタンでこの画面に戻れます（ROM は読んだまま。「編集に戻る（ファイル名）」で編集画面に戻ります）。Language を切り替えると、この画面の文字もその言語になります。

- **ROM を開く…**: ファイルを選んで開きます。この画面へ `.gba` ファイルをドロップしても開けます。
- **最近開いた ROM**: 開いた ROM を新しい順に 8 件まで覚えています（`settings.ini` の `RecentRoms`）。クリックで開き、ゲームの種類（ファイアレッド・エメラルド）がバッジと名前で分かります。無くなったファイルは「見つかりません」と出て、クリックすると一覧から外せます。「一覧を消す」で全部消えます（ファイルは消しません）。
- **ヘルプ**: README・リリースノート・`docs` フォルダ・`resource` フォルダを開きます（exe の隣に無いものは薄く表示されます）。
- **このツールについて**: バージョン・作者と、使う上での注意。**使いかた**: 開く → マップを選んで描く → 確定 → 保存、の流れ。

ウィンドウの位置と大きさ（最大化しているか）は閉じるときに `settings.ini`（`MainWindow`・`MainWindowMaximized`）に保存され、次回同じ大きさで開きます。初回は、画面の作業領域より少し小さい大きさで中央に開きます。

### イベントスクリプトのポインタアドレス取得
イベントヘッダ内で「スクリプトのアドレスが書かれている場所」（ポインタ自体のアドレス）を `08XXXXXX` 形式でクリップボードにコピーする機能です。
スクリプト本体のアドレスではなく、ポインタの置き場所を返す点に注意してください。

1. マップを読み込み、編集モードのタブを「イベント」に切り替える
2. イベント種別で **歩行グラフィック** / **踏むスクリプト** / **看板** のいずれかを選ぶ（ワープはスクリプトを持たないため対象外）
3. イベント番号で対象のイベントを選ぶ
4. 「スクリプト :」ラベル、またはその隣のスクリプトアドレス入力欄を **右クリック**
5. **ポインタのコピー** をクリックすると、ポインタアドレスがコピーされダイアログで表示される

イベントデータ未読込やイベント番号が無効なときはメニュー項目がグレーアウトします。
種別が上記3つ以外のときは「スクリプトを持つイベントを選択してください。」と表示されます。

### このマップのポインタ一覧と、アドレスの参照元の検索
アドレスをメモに書き写して手でリトルエンディアンに直し、バイナリエディタで探す作業を、エディタが代わりに行います。

開き方（どれでも同じ画面が開きます）
- イベントタブの上部にある **「ポインタ一覧を確認」ボタン**（画像のボタン。ツール欄を分離していても押せます）
- イベントタブの「スクリプト :」欄を右クリック →「このマップのポインタ一覧を開く…」
- `Ctrl + Shift + P`
- 「マップの設定」タブ →「詳細な値を表示」→ 先頭のボタン

上の一覧: マップに関係するポインタ（マップ見出し・地形データ・タイルセット・イベント・人物や看板のスクリプト・マップスクリプト・接続）を、分類・項目・置き場所・値・バイト列で表示します。
- **置き場所** = そのポインタの 4 バイトが書かれている場所のアドレス（CFRU の repoints などに書く値）
- **値** = そこに書かれているアドレス（スクリプトなどの本体の場所）
- **バイト列** = 値をリトルエンディアンで並べたもの（例 `56 34 12 08`。バイナリエディタの検索欄にそのまま貼れます）
- 行を選んでボタンを押すか、セルをダブルクリックするとコピーします。複数行も選べます。「行をコピー」はタブ区切りです。

マップとの連動: 一覧を開いたまま、マップ上でイベントをクリックする（またはイベントタブで種類・番号を変える）と、一覧の該当する行へ移動して色が変わります。逆に、一覧でスクリプトの行をクリックすると、マップ側でそのイベントが選ばれ、画面に入るようにスクロールします。連動するのは、スクリプトを持つ人物・踏むスクリプト・看板です。

下の「アドレスの参照元を探す」: アドレスを入れて「参照元を探す」を押すと、そのアドレスを指している場所を ROM 全体から探して並べます。
- 入力は `08123456`・`123456`・`56 34 12 08` のどの形でも受け付けます。
- マップのデータの表にある場所は、どのマップの何かを説明に出します（例「(3, 0) マサラタウン: 人物 / 人物 1 のスクリプト」）。
- 「選んだ行の値で探す」で、上の一覧で選んだポインタの値をそのまま探せます。

### 新しいマップを作る（「データ作成」タブの手順ガイド）
「データ作成」タブは、新しいマップを作る順に ①〜⑦ の枠を並べています。右上の「＋ マップを追加…」でバンクにマップを足して（または使っていないマップを選んで）から作り替えます。

「マップを追加…」: 選んだバンクの最後に、今選んでいるマップをもとにしたマップを 1 つ足します（見出しの設定・地形データの形・タイルセットを写し、イベントとマップスクリプトは空、接続は無し）。バンクのマップ一覧と地形データの表の後ろに空きが無いときは、確認のうえ空き領域へ移して参照を付け替えます。すぐに ROM（メモリ上）へ書き込むので、最後に「ROMを保存」を押してください。
バンクの一覧のいちばん下の「新しいバンク ○ を作る」を選ぶと、新しいバンクを作って、その 0 番のマップとして足します（バンクの表も、後ろに空きが無ければ空き領域へ移して参照を付け替えます）。

1. タイルセットを用意する（使い回すなら飛ばす。別の ROM から移すときは「マップタイル」タブ）
2. マップの形（地形データ＝マップフッター）を作る。「書き出したマップの並びから作る…」で、マップタイルの書き出しに入っている並び・ボーダーをそのまま使うこともできる（タイルセットは②の欄の番号。「マップタイル」タブでまとめて取り込むと、作った番号が自動で入る）
3. 「作った地形データを割り当てる」で、選んでいるマップに設定する
4. 「マップ」タブでブロックと移動エリアを塗り、「編集中のMAPを確定」
5. イベントを置く（作ると今のマップに付く）
6. 必要ならマップスクリプト・接続を作り、「作ったマップスクリプト・接続を割り当てる」
7. マップ名・出現ポケモン・BGM を決め、「ROMを保存」

「（共有データ）」と付いた項目（パレット・マップ名）は、同じデータを使うほかのマップも変わります。割り当ては確定するまで ROM に書かれません。

### マップの大きさを変える
「マップの設定」タブの「マップの大きさ」の右にある **「大きさを変える…」** を押します。
- 新しい幅・高さ（ファイアレッドはボーダーの幅・高さも）と、広がった部分を埋めるブロックを決めます。今の内容は左上をそろえて残ります。小さくすると、はみ出した部分は無くなります。
- **左側に足す列数・上側に足す行数**を入れると、中身がその分だけ右・下へずれて、左・上に広がります（負の値なら左・上を削ります）。入れた分だけ新しい幅・高さも自動で増えます。このとき、イベントの座標、このマップの接続のずれ、相手のマップの接続のずれ（このマップへ戻ってくる接続）も一緒に直します。相手のマップの分は「編集中のMAPを確定」のときに書きます。左・上にはみ出すイベントは 0 の位置に寄せます。
- 新しい並びは空き領域に作ります（書き込み先は一覧から選びます）。元の並びはそのまま残るので、ほかのデータを壊しません。
- 大きさが変わるのは **「編集中のMAPを確定」を押したとき** です。確定せずに別のマップへ移ると元の大きさのままで、確保した空き領域も元に戻ります。
- 下の欄に、必要な空き領域、新しい大きさの外に残るイベントの数、同じ形を使い回しているマップの数が出ます。ゲームが読み込める大きさ（(幅 + 15) × (高さ + 14) が 10240 以下）を超える指定はできません。
- 同じ形を使い回しているほかのマップは、大きさは一緒に変わりますが、それらのイベント・接続のずれは直しません。

### イベントの追加と削除（人・看板・踏むスクリプト・ワープ・アイテム）
「イベント」のモードで、マップに直接イベントを置けます。

- **追加**: マップの上を **右クリック** して「ここに「歩行グラフィック」を追加」「看板」「踏むスクリプト」「ワープ」を選ぶと、その場所に 1 つ増えます。右の欄の **「＋ 追加」** は、上で選んでいる種類を、見えているマップの中央に追加します（追加した後、ドラッグで動かせます）。
- **削除**: 右クリックのメニューの「…番を削除」、右の欄の **「削除」**、または **Delete キー** で、選んでいるイベントを消します。
- **アイテム（落とし物）**: 右クリックの「ここにアイテム（落とし物）を追加…」で、アイテムと、拾った後に消すためのフラグを決めると、モンスターボールの形の落とし物が置かれます。見た目・向き・階層は、その ROM にある落とし物に合わせます。アイテムを渡すスクリプトは、確定のときに自動で用意します（同じアイテムのスクリプトが ROM にあればそれを使い、無ければ空き領域に作ります）。フラグの欄には、どのマップの人のイベントも使っていない番号が初めに入りますが、スクリプトの中だけで使われている番号までは調べていないので、気になるときは自分で決めてください。
- 追加・削除は「戻る」「進む」で取り消し・やり直しができます。
- ROM へは今までどおり **「編集中のMAPを確定」** で書きます。イベントの数が増えていれば、確定のときに空き領域へ新しい入れ物を作って付け替えます（古い入れ物は、ほかのマップが使っていなければ空きに戻します）。空き領域が足りないときは、何も書かずに止まります。
- 追加したイベントの初めの値: 人は見た目 0 番・下向きで動かない・スクリプトなし。看板・踏むスクリプトはスクリプトなし。ワープの行き先は今のマップの 0 番（置いた後で直します）。
- 1 つのマップに置ける数は、人が 64 個、ほかは 255 個までです。隠しアイテムは、看板を追加してから種類を隠しアイテムにします（「隠しアイテムの看板」の項）。


### 隠しアイテムの看板
イベントタブで看板を選び、タイプを「隠しアイテム」（05〜07）にすると、スクリプトの欄の代わりに **道具・フラグ**（ファイアレッドは **個数・真下専用** も）の欄が出ます。
- 道具の番号の下に、ROM から読んだ道具の名前が出ます（道具のデータの形を作り替えた改造版では出ません）。
- フラグは、隠しアイテム用のフラグの先頭（ファイアレッド 0x3E8、エメラルド 0x1F4）からの数です。下に実際のフラグ番号が出ます。
- 「真下専用」は、正面から調べても拾えず、真上でダウジングマシンを使ったときだけ見つかる置き方です。

### 出現ポケモン（ファイアレッド・エメラルド）
「出現ポケモン」タブは、エメラルド（日本語版・英語版・改造版）でも使えます。ポケモンの名前と匹数は ROM から読みます（改造版で増やしたポケモンも一覧に出ます）。

### マップ作成補助（パーツの指定・サポート作成）
「どのブロックが何のパーツか」をタイルセットごとに指定しておき、その指定を使ってマップを塗る・整える画面です。「データ作成」タブの ④ の枠の **「マップ作成補助を開く…（パーツ・サポート）」** で開きます（マップを切り替えても開いたままで、中身が入れ替わります）。

#### パーツの指定

- 左でブロックを選びます。「ブロック一覧」はクリックかドラッグ、「マップ」は今のマップの上をドラッグして範囲を選びます。
- 真ん中でパーツを作り、右の「← 左で選んだ所を入れる」で中身を入れます。パーツの種類は 4 つです。
  - **面**: 地面・草むらなど、同じ役割で置き換えられるブロックの集まり。
  - **縁つき**: 水・道・崖など、境目に専用のブロックがある地形。外側の縁 9 個（中央・辺・角）と内側の角 4 個の枠に入れます。3×3 を選んで入れると外側の 9 個、2×2 なら内側の角をまとめて入れられます。
  - **部品**: 家・大きい木など、決まった並び。「マップ」で範囲を囲んで入れると、移動エリア（通れる・通れない）も一緒に覚えます。
  - **くり返し**: 森のように同じ並びを広げるもの。「上端」「くり返す単位」「下端」に入れます（幅は同じにします）。
- 役割（地面・草むら・道・水・木・崖・柵・建物・飾り・その他）を選ぶと、ブロック一覧の指定済みのブロックに、役割の色の印が付きます。
- **「マップから候補を作る（自動）」** を押すと、ROM の中でこのタイルセット 1 を使っている全マップの並びと、ブロックの挙動（草むら・水・段差・入口）から、パーツの候補をまとめて作ります。名前が「自動: 」で始まるパーツが候補です（地面・地面（くり返し）・草むら・水（縁つき、絵柄ごとに 3 つまで）・水（ほか）・段差・森・崖・壁・建物・飾り・小物）。候補は大まかなもので間違いを含むので、中身を確かめて直してください。部品の候補で斜線のマスは「空き」（その場所は変えない）です。もう一度押すと、名前が「自動: 」のままのパーツだけを作り直します（名前を変えたパーツと自分で作ったパーツは残り、そこで使っているブロックは面の候補から外れます）。
- 「指定を保存」で、exe と同じ場所の `resource\mapassist` に、タイルセット 1 つにつき 1 ファイルで保存します。タイルセット 1 と 2 の両方のブロックを使うパーツは、タイルセット 2 のファイルに入ります。
- 保存した指定は、ブロックのデータが同じタイルセットなら、別の ROM や別の場所でもそのまま使えます（「マップタイル」タブでタイルセットを移した先など）。ブロックを編集して中身が変わった後は、同じ ROM の同じタイルセットとして読み込みます。
- パーツの指定は ROM を書き換えません。

#### サポート作成（試作）
画面の右端の枠で、指定したパーツを使って編集中のマップを塗ったり整えたりします。

1. 左の「マップ」タブで、範囲をドラッグして選びます（左下に「選択: マップの (x, y) から 幅 ○ × 高さ ○」と出ます）。
2. 真ん中の一覧で、使うパーツを選びます。塗る前に、右の「中身」の絵が合っているか確かめてください（自動の候補は外れていることがあります）。
3. **「選んだパーツで範囲を塗る」** を押します。
   - 面: 右の欄で選んだブロック（選んでいなければ先頭）で塗ります。
   - 縁つき: 中央のブロックで塗ってから、周りの縁（辺・角・内側の角）を付けます。
   - くり返し: 範囲に並べ、いちばん上・下の行に上端・下端を付けます。
   - 部品: 範囲の左上に置きます（1 マスクリックするだけで十分です）。
4. 必要なら **「範囲を整える」** を押します（範囲を選んでいなければマップ全体）。対象は**縁つき**と**くり返し**のパーツです（面・部品は塗るだけ）。
   - 縁つき: つながった所ごとに、辺・角のブロックへ置き換えます。
   - くり返し: 並びのずれを直します（上端・下端は塗るときに付きます）。
   - 移動エリア: パーツで決めた値（無ければ ROM のマップでいちばん多い値）を付けます。建物を置いた後は、入口の値が変わらないように、このチェックを外して整えるのがおすすめです。
   - 元からある池の角や 1 本だけの木など、既に正しい所は変えません。

塗る・整えるは 1 回ずつ、メインの画面の「戻る」（Ctrl+Z）で元に戻せます。ROM へは、今までどおり「確定」してから「ROMを保存」で書き込みます。

### マップ作成補助：ランダム作成（試作）
「サポート作成」の枠の下の **「ランダム作成…（ゼロから作る）」** で、指定したパーツからマップのたたきを作ります。

- 設定: 乱数の種（同じ種と設定なら同じ結果）、森・水・草むらの割合（%）、建物の数、小物の数、まわりを森で囲むか、建物から道を引くか、作る範囲（選んでいる範囲かマップ全体）。
- 使うパーツは役割で決まります: 地面（面。くり返しの地面があればその模様）、木・森（くり返し）、水（縁つき。内側の角が無いときは楕円の池だけ）、草むら（面）、建物（部品）、道（面）、飾り（面・部品）。無い役割は省いて、案内に出します。
- 作る順: まわりの森 → 建物（入口の下 1 行を空ける）→ 道（建物の入口から中心へ L 字）→ 水 → 森のかたまり → 草むら → 小物 → 水の縁と移動エリアを整える。
- 結果はたたきです。メインの画面の「戻る」（Ctrl+Z）で 1 回で元に戻せます。候補の自動作成のパーツをそのまま使うと、岸の絵柄が混ざるなどの外れが出るので、パーツを直してから作り直すときれいになります。

### 自動ペン（なぞるだけで岸・段差・木・建物ができる）
「マップ」タブの道具に **「自動ペン (P)」** があります。使い方はペンと同じで、右の「ブロック」の一覧でブロックを選んで、マップをなぞるだけです。選んだブロックに合わせて、次のように自動で描きます。

- **水・崖・砂の道のブロック**: なぞった所のまわりに、縁（岸・段差・角）が自動で付きます。山のように縁が二重のものは、内側の縁も付きます。
- **木のブロック**: 木を 1 本ずつ置きます。なぞると森になり、上下の木の重なりと、森の端の絵が自動で付きます。近くの木と位置がそろいます。
- **建物・看板などのブロック**: 建物をまるごと 1 つ置きます（選んだブロックが、クリックした所に来ます）。
- **地面・草むらなどのブロック**: そのブロックで塗り、移動エリアも一緒に付けます。
- それ以外のブロックや、ブロックをまとめて選んでいるときは、ペンと同じように塗ります。

道具を選んでいる間、道具のボタンの下に 1 行の案内（今のブロックがどう描かれるか）と「筆の大きさ」（1・2・3・5 マス）、画像ボタン「タイル自動化設定を開く」が出ます。カーソルには、置く物の絵が透けて出ます。右の「ブロック」の一覧では、自動で描けるブロックに薄い紅色が重なります（紅くないブロックは、ペンと同じ動きです）。マップの上で右クリックすると、その場所のブロックを拾えます（ペンと同じ）。1 回のドラッグが 1 回の「戻る」（Ctrl+Z）です。ROM へは今までどおり「編集中のMAPを確定」で書きます。

**グループ分け（どのブロックが水・崖・木・建物か）**

- ファイアレッド（日本語版）の共通タイルセット（地面・草むら・花・砂の道・池・岩山・木）と、エメラルド（日本語版・英語版）の屋外の共通タイルセット（地面・草むら・長い草・花・砂の道・明るい草地・池・岩山・木・森）は、元のゲームのマップで確かめた指定を同梱しています（`resource\mapassist`）。改造 ROM の Spades（2025.04.11 版 0.2.1）も、標準の屋外タイルセットと、独自マップ用のタイルセット 2 つ（IRIS CITY などの町・道路用と、SERENITY FOREST などの森用）の指定を同梱しています。改造 ROM でも、同じ場所か同じ中身のタイルセットならこの指定が使われます。
- 指定の無いタイルセット（町ごとのタイルセット 2 や、自作・エメラルドなど）は、初めて道具を選んだときに ROM のマップでの使われ方から自動で調べて保存します（少し時間がかかります）。自動の判別は外れることがあります。
- 岸や崖が正しく付かないときは、帯の **「タイル自動化設定を開く」** ボタンで「マップ作成補助」を開いて直すと、自動ペンにも反映されます。

### 表示機能の選択（右のツール欄に出す機能）
右のツール欄の上にある **「表示機能の選択」** ボタンを押すと、ツール欄に出す機能（操作ボタン・マップチップ取り込み・マップ移動・タウンマップ・イベント表示の切り替え・選択ブロックとボーダー）を、チェックで選び、「上へ」「下へ」で並べ替えられます。「初めの状態に戻す」で、表示・並び順・分離をすべて戻します。

### 移動エリア・イベントの印の濃さ
- 「移動エリア」「イベント」のタブでは、マップの下（「グリッド線描画」の右）に**濃さのスライダー**が出ます。右へ動かすと、マップに重ねる印（移動エリアの `0`・`1`・`C` など、イベントの `W`・`S`・`T` など）が濃くなり、左へ動かすと薄くなります（10〜100%。初めは今までと同じ 60%）。
- 濃さは移動エリアとイベントで別々に覚え、次に起動したときも同じ濃さで出ます（`settings.ini` の `CollisionOverlayOpacity`・`EventOverlayOpacity`）。

### タイルアニメ再生
右の操作パネルの **「タイルアニメ再生」** にチェックを入れると、今のマップの花・水面・噴水・湯気などが、ゲームと同じように動きます（チェックを外すと止まり、元の絵に戻ります）。

- アニメの定義は、タイルセットの見出しが指す「アニメ処理」（ゲーム本体のプログラム）を読んで取り出します。ファイアレッド・エメラルドとも、日本語版・英語版・改造版で使えます（処理の作りが大きく違う改造版では、アニメ無しになることがあります）。
- 動かすのは表示だけで、ROM や編集中のマップは変えません。
- 「接続マップを表示」で出している接続先のマップも、その地形データのタイルセットのアニメで一緒に動きます（接続先は灰色寄りの表示のまま）。

### マップタイルの移植（別の ROM へタイルセットを移す）
「マップタイル」タブから使います。タブには、選んでいるマップの書き出す内容（タイルセットごとの枚数など）、使い方、プレビュー（マップ全体・タイルセット 1・2 のブロック）が出ます。

書き出し（「マップタイルをエクスポート」）: 選んだ場所に `map_<バンク>_<番号>_<マップ名>` フォルダを作り、次のファイルを出します。書き出すのは確定済みの内容なので、未確定の変更があるときは先に確定してください。
- `tileset1.png` / `tileset2.png` … タイルの絵（16 色の番号付き PNG。「タイルセットを作成」でもそのまま読めます）
- `tilesetN_paletteNN.png` … パレット 1 本ずつ（「パレットを変更」でそのまま読めます）
- `tileset1_blocks.png` / `tileset2_blocks.png` … ブロックを横 8 個ずつ並べた絵（一部だけ取り込むときに使います）
- `map_preview.png` … マップ全体の絵
- `map_info.txt` … ゲーム・マップの大きさ・並び・ボーダー、タイルセットごとのパレット 16 本・ブロック・挙動（数値は 16 進）

取り込み（「マップタイルをインポート」）: 書き出したフォルダを選び、取り込み方を選びます。
- まとめて取り込む: タイルセット 1・2 の片方または両方を、空き領域に新しいタイルセットとして作ります（タイル・パレット・ブロック・挙動をすべて入れる）。書き込み先は空き領域の一覧から選びます。作った後は「マップの設定」タブや「マップフッターを作成」でその番号を指定して使います。タイルアニメは、書き出しにコマの絵（`tileset1_anim00.png` など）と見出しの「アニメ処理」の場所を入れ、**同じゲームの ROM へ取り込むときに、取り込み先の同じ場所に同じ処理（同じ差し替え先・枚数・速さ・コマの絵）があれば引き継ぎます**（別の改造版や形の違うゲームでは引き継げないので、取り込んだ後に付け直してください。結果は取り込み後の案内に出ます）。
  - **FR ⇔ エメラルド**のように形の違うゲームへは、自動で変換して取り込みます: タイルセット2 のタイル番号（第 1 のタイル数 640/512 の違い）とパレット 6 番の受け持ち（FR は 0〜6/7〜12、エメラルドは 0〜5/6〜12）を付け替え、挙動を 4 バイト ⇔ 2 バイトに直します（挙動の番号は同じ並びとして写すので、違う所は取り込み後にブロックエディターで直してください）。取り込み先に置ける枚数を超えるタイルは、ブロックが使っているものだけに詰め直し、それでも超えるときは書き出したマップが使っているブロックだけを残します（ほかのブロックは空）。変換の内容は取り込みの画面と、取り込んだ後の案内に出ます。
- 一部だけ取り込む: ブロック一覧の絵をドラッグして範囲を選び、「マップチップ取り込みへ…」で今のマップのタイルセットへ取り込みます（ウィザードで取り込み先・パレット枠・置き場所を選ぶ）。色はパレット 1 本に減色されます。FR とエメラルドの間でも使えます。

## CLI対応方針

### 今回対応した内容
- `features`
  現在の機能棚卸とCLI対応状況の出力
- `rom-info`
  ROMタイトル、コード、サイズ、SHA-256の出力
- `find-free-space`
  空き領域検索
- `decode-text`
  指定オフセットの文字列デコード
- `export-pokemon-names`
  ポケモン名一覧の書き出し
- `export-item-names`
  アイテム名一覧の書き出し
- `export-move-names`
  技名一覧の書き出し
- `export-trainer-class-names`
  トレーナー肩書き一覧の書き出し
- `item-info`
  個別アイテム情報の取得
- `pokemon-stats`
  種族値・努力値・タイプ・特性・持ち物・タマゴ関連・捕獲率などの読取
- `export-pokemon-stats-csv`
  種族値関連の一括編集用CSVを書き出し
- `import-pokemon-stats-csv`
  `export-pokemon-stats-csv` で出した列構成のCSVを一括反映
- `update-pokemon-stats`
  `pokemon-stats` 対象の基本更新
  基礎値6種、努力値6種、タイプ、特性、持ち物、性別値、タマゴ歩数、タマゴグループ、捕獲率、なつき度、成長率、逃走率、体色、図鑑向きに対応
- `trainer-info`
  トレーナーデータ本体と手持ち一覧の読取
- `update-trainer`
  トレーナー本体の基本更新
  肩書ID、BGM、スプライトID、名前、所持アイテム4枠、ダブルフラグ、AI、未知値、手持ち1枠のポケモン/レベル/IV/未知値/アイテム/技更新に対応
  `--data-type` と `--pokemon-count` による手持ち構造変更、`--start` / `--pokemon-data-address` による再配置にも対応
- `import-images`
  画像導入CLI
  `pokemon-sprite` は 256x64 の4分割画像から正面/背面/通常パレット/色違いパレットを一括導入
  `item-image` は 24x24 の画像とパレットを一括導入
  `pokemon-icon` は 32x64 の手持ちアイコン画像を導入し、必要に応じてパレットIDも更新
  `trainer-image` は 64x64 のトレーナー画像とパレットを一括導入
  `--vanilla` 指定時は `PokedexOrder` を使って全国図鑑順IDから内部IDへ変換
  `--neworder` 指定時はエディタ上の並びをそのまま使用
- `export-images`
  ROM内画像の一括エクスポート
  `pokemon-sprite` は import 可能な 256x64 形式で出力
  `item-image` / `pokemon-icon` / `trainer-image` もPNGで出力
- `export-image-sheet`
  画像一覧シート出力
  1行16マスで `pokemon-sprite` / `pokemon-icon` / `item-image` / `trainer-image` をPNG化
  `pokemon-sprite` は `front-normal` / `front-shiny` / `back-normal` / `back-shiny`
  `pokemon-icon` は `frame1` / `frame2` / `full` を選択可能
